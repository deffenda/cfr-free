## P1-01 — Regulatory graphics silently disappear

**Status:** OPEN. **Implementation risk:** MEDIUM (parser/runtime).
**Harm:** A researcher reading hearing-rating criteria receives a provision
with its rating tables missing and no warning that the response is incomplete.

Evidence: `src/core/xml.ts:219-235` renders text descendants but does not
preserve image attributes. On the eCFR `2026-10-16` Title 38 XML, section
`4.85` contains `/graphics/er11my99.005.gif` and
`/graphics/er11my99.006.gif`; neither link occurs in parsed text/markdown.
The full fetched document contains 15 `<img>` elements. These are historical
observations, not future fixed corpus counts.

Reproduce after `npm run build`, from the checkout root:

```bash
node --input-type=module <<'JS'
import { parseTitleXml } from './dist/core/xml.js';
const url = 'https://www.ecfr.gov/api/versioner/v1/full/2026-10-16/title-38.xml';
const response = await fetch(url);
if (!response.ok) throw new Error(`upstream HTTP ${response.status}`);
const xml = await response.text();
const start = xml.indexOf('N="4.85"');
console.log(xml.slice(start, xml.indexOf('</DIV8>', start)).match(/<img\b[^>]*>/gi));
const section = parseTitleXml(xml).find(row => row.citation === '4.85');
console.log(section?.text, section?.markdown);
JS
```

Proposed first packet: preserve a source link and an explicit unavailable
image-content marker in both representations; handle images nested inside
paragraphs and containers, not just direct division children. Restrict source
references to verified eCFR graphics paths/URLs; reject hostile schemes and
unexpected hosts. Keep serving offline: no implicit graphic fetch or OCR.
Do not advertise textual table parity until separately verified transcription
or local asset support exists. Record parser-version implications in refinement.

Candidate scope: `src/core/xml.ts`, `src/core/sync.ts`, `test/xml.test.ts`,
`test/fidelity.test.ts`, `docs/SPEC.md`, `README.md`.
Acceptance: an offline fixture derived from § 4.85 retains both references
and incompleteness notices; nested-image, missing-src, hostile-src, and
text-only regressions pass. Existing prose/table order stays intact. Inspect
the actual MCP/HTTP section payload after sync. A fresh index must not imply
complete textual coverage solely because section counts match.
Targeted check: `npm test -- test/xml.test.ts test/fidelity.test.ts test/sync.test.ts`.
Full gate: `npm run ci`; optional live check: `LIVE_TESTS=1 npm test -- test/live.test.ts`.

## P1-02 — Late responses overwrite the active UI route

**Status:** OPEN. **Implementation risk:** MEDIUM (browser behavior).
**Harm:** A user can see § 4.125 content while the active URL names § 4.130,
making it possible to associate the wrong criteria with the selected citation.

Evidence: `src/titan/ui.ts:437-454` unconditionally renders resolved section
requests; `:364-371` does the same for searches. A controlled deferred-fetch
probe requested 4.125, navigated to 4.130, resolved 4.130 first, then 4.125:
final hash `#/section/4.130`, heading `Heading 4.125`, body `Body 4.125`.
Reproduce with deferred promises, not real sleeps or network timing.

Proposed packet: use a route/request generation guard, incremented on every
navigation including empty/search/browse routes. Only the current generation
may mutate content, metadata, references, pager, or errors. Cancellation may
save work but cannot replace checking ownership after response-body parsing.
Audit browse callbacks against the same rule during refinement; bound any
necessary changes in the packet before implementation.

Candidate scope: `src/titan/ui.ts`, `test/http-server.test.ts`, a **new proposed**
`test/ui.test.ts`, `docs/SPEC.md`. Use existing test/runtime facilities; if a
browser library is needed, report the need instead of installing it.
Acceptance: execute the served UI JavaScript with controlled DOM/fetch stubs
or an already available browser harness. Reverse response order for section
and search navigation; latest route wins. Late success, late error, delayed
JSON parsing, cross-view navigation, and clearing the query cannot repaint
the current view. References must not accumulate from obsolete responses.
Existing `test/http-server.test.ts:683-691` asserts JavaScript source text;
surface those assertions in the report and add behavioral coverage rather
than treating string presence as proof of correct execution.
Targeted check: `npm test -- test/http-server.test.ts test/ui.test.ts`
(include the second path only after creating the proposed test). Full gate:
`npm run ci`. Disclose whether browser execution or a DOM stub was used.

## P1-03 — Display citations do not round-trip through input parsing

**Status:** OPEN. **Implementation risk:** MEDIUM (shared citation behavior).
**Harm:** A user copying the product's legal citation into its section-read
tool receives invalid input instead of the regulation the product displayed.

Evidence: display format `38 C.F.R. § 4.130` is emitted by
`src/core/service.ts:198-200`; title stripping at
`src/core/citations.ts:30-34` accepts `CFR` but not dotted `C.F.R.`.
Reproduce after building:

```bash
node --input-type=module <<'JS'
import { normalizeCitation } from './dist/core/citations.js';
for (const citation of ['38 C.F.R. § 4.130', '38 CFR 4.130']) {
  console.log(citation, normalizeCitation(citation));
}
JS
```

Observed: first returns `null`; second returns section citation `4.130`.
Proposed packet: accept the project's emitted dotted Title 38 format while
preserving strict title isolation, length bounds, appendix handling, and
existing accepted forms. Paragraph-designator support for direct reads is
outside this packet unless explicitly refined; search already strips them.

Candidate scope: `src/core/citations.ts`, `test/citations.test.ts`,
`test/service.test.ts`, `test/mcp-server.test.ts`, `test/http-server.test.ts`,
`docs/SPEC.md`. Acceptance: take a real search hit's `citationDisplay` and
feed it to `getSection`; same section results. Test mixed case, whitespace,
§ forms, trailing punctuation, appendix regressions, wrong-title rejection,
and junk/injection inputs. Exercise HTTP and MCP using emitted display text.
Targeted check: `npm test -- test/citations.test.ts test/service.test.ts test/mcp-server.test.ts test/http-server.test.ts`.
Full gate: `npm run ci`; no public field changes required by this proposal.

## P1-04 — Primary Quickstart requires an unpublished npm package

**Status:** OPEN. **Implementation risk:** LOW for documentation correction;
release/publishing changes are a separate HIGH/operator-controlled task.
**Harm:** A new user following the first installation command cannot install
the tool and may abandon onboarding before reaching the later caveat.

Evidence: `README.md:41` leads with `npm install -g cfr-free`; `:79-83`
acknowledges inactive trusted publishing. Live registry probe on 2026-10-20:
`curl -sS -o /dev/null -w '%{http_code}\n' https://registry.npmjs.org/cfr-free`
returned `404`. Repeat the probe: registry state can change.

Proposed packet: make the primary path a verified source checkout/build/run
sequence, including the working directory, commands, and verification output.
MCP configuration must invoke the built absolute CLI path or explain how
the executable is installed. Keep npm instructions conditional until a real
publication is verified. Never activate publishing, push tags, change release
CI, or install dependencies as an agent to close this documentation finding.
Human-facing setup may document installation commands; verify build/run
against already provisioned dependencies and disclose that limitation.

Candidate scope: `README.md` only. Acceptance: cleanly ordered source setup,
sync, HTTP and MCP examples, with no unqualified unavailable npm path. Run
the built CLI's `version`; use an isolated temporary index for an opt-in
live smoke. Confirm the package entrypoint against `package.json` and
`src/cli.ts`. Validation: `node_modules/.bin/prettier --check README.md`,
`npm run typecheck`, and the repo pre-commit validator. Do not claim a clean
installation was tested when installs were forbidden.
