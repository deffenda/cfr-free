## P1-20261021-07 — The browse view shares the redline view's race

**Status:** OPEN. **Implementation risk:** MEDIUM.
**Evidence:** `src/titan/ui.ts:805` — a tree click calls
`loadBrowseLevel(childLevel(level, entry), routeGeneration)`, and the only
guards on that path are the route guard (`:886`, `:903`).
`routeGeneration` advances at exactly one place, `:941`, which runs on
NAVIGATION only. So two in-flight browse fetches share one guard, and a
late response from an earlier click can push its level onto `browseLevels`
(`:893`) and repaint over a later click's result. Compare the redline
view's per-request identity (`src/titan/ui.ts:190`, `:524`, `:538`).

**Where it came from:** the REVIEW of finding 01, not from the audit — the
audit's finding-01 text never mentions the browse view. It is a
pre-existing defect of the same class, on `main` before this round.

**Implementation reference:** the redline round's request-identity pattern
(#111) applied to the browse path, with the same invalid-submission policy
and the same test matrix. **Not yet dispatched** — the free-model pool was
exhausted when the round came due, so it is next in the queue rather than
in flight.

## P1-20261021-01 — Older redline submission overwrites the newer one

**Status:** OPEN. **Implementation risk:** MEDIUM.
**Evidence:** `src/titan/ui.ts:494-537`, especially the generation checks
at 508 and 521 and the submission at 537 (main baseline).
Submissions reuse `routeGeneration`; only route navigation increments it.
The callbacks therefore cannot distinguish two submissions on `#/redline`.

**Reproduce:** use the existing behavioral harness in `test/ui.test.ts`
(`makeHarness`, `PendingCall`, and the redline-view tests). Navigate to
`#/redline`; submit from `2026-01-01` to `2026-06-01` for `4.125`, then
submit the same dates for `4.130`. Resolve the second request successfully,
then the first. The executed UI script produced:

```text
currentFormCitation: 4.130
displayedHeading: Section 4.125: changed
displayedBody: ... body 4.125
```

**Harm:** a researcher requesting a new provision receives the older
comparison under the newer form state and can use the wrong comparison.

**Candidate manifest:** `src/titan/ui.ts`, `test/ui.test.ts`; SPEC only
if the refined contract needs clarification.
**Acceptance:** a distinct request identity owns each submission. Older
successes, network errors, HTTP errors, and delayed JSON bodies cannot
overwrite the latest submission. Invalid submissions must also have a
decided invalidation policy. Preserve the navigation-away guard.
**Checks:** UI behavioral suite with controlled response order, then
`npm run ci`; no network sleeps or new browser dependencies.

## P1-20261021-02 — Grounding treats scattered words as a quoted phrase

**Status:** OPEN. **Implementation risk:** MEDIUM.
**Evidence:** `src/core/store.ts:672-675` (`termResponded`), consumed by
`visibleMatches` and `src/core/service.ts`'s `grounding` (main baseline).
The predicate uses `every`/`some` over words anywhere in the hit rather
than an ordered phrase, and applies prefix matching to each phrase word.

**Reproduce:** seed a temporary store using `makeSection` and
`openTempStore` from `test/helpers.ts`, with one row:

```text
citation: 1.1
heading: Compensation.
text: Compensation includes attendance records and emergency aid.
query: "aid and attendance" compensation
```

Through `CFRService.search`, the observed result was total 1,
`matches: ["aid and attendance", "compensation"]`,
`matchedTerms: ["aid and attendance", "compensation"]`, and
`unmatchedTerms: []`. The phrase-only query `"aid and attendance"`
returned total 0 from the same store.

**Harm:** HTTP/MCP clients receive a false grounding claim, and the UI
suppresses its missing-term caution despite the requested phrase being absent.

**Candidate manifest:** `src/core/store.ts`, `test/store.test.ts`,
`test/service.test.ts`; SPEC only for a deliberate contract adjustment.
**Acceptance:** grounding respects phrase order, adjacency, and the
search's token/prefix rules for quoted spans and synonym phrases. Verify
positive matches and negative scattered/reversed-word cases through the
service envelope as well as per-hit matches. Preserve token boundaries.
**Checks:** store/service tests, then `npm run ci`.

## P1-20261021-03 — npm release job omits the built CLI

**Status:** OPEN. **Implementation risk:** HIGH (release infrastructure).
**Evidence:** `.github/workflows/release.yml:114-130`, `package.json`'s
`bin`, `files`, and scripts (main baseline). The job checks out, runs
`npm ci`, and publishes, with no build or artifact download. The separate
CI job's build output is not transferred; no package lifecycle hook builds it.

**Reproduce:** archive the pinned revision into a fresh temporary directory
outside the working tree. Run `npm pack --dry-run --ignore-scripts --json`
there; this installs nothing and publishes nothing. Observed file list:

```text
LICENSE
README.md
package.json
dist/cli.js present: false
```

The bin target is `dist/cli.js`. `git ls-files dist` returns no files.
At audit time `gh variable list --json name,value` returned `[]`, so the
`NPM_TRUSTED_PUBLISHING == 'true'` activation condition was disabled.

**Harm:** when the operator enables publishing, the job can publish an
unusable package without the advertised executable. No existing broken
published release was established by this audit.

**Candidate manifest:** `.github/workflows/release.yml`; release/package
validation documentation or tests only as justified during refinement.
**Acceptance:** the publishing job builds or receives the matching artifact,
verifies that the packed executable and its imports exist, and performs a
non-publishing executable smoke. Preserve version matching, provenance,
trusted-publisher activation, and operator control. The fix must not enable
publishing. Name these invariants in the independent HIGH-risk review.
**Checks:** `npm run ci`, fresh-checkout package inspection and packed-CLI
smoke; operator sign-off before merge. Never validate with a real publish.

## P1-20261021-05 — Pilot timing template uses the wrong threshold

**Status:** OPEN. **Implementation risk:** LOW (research documentation).
**Evidence:** PR #103, merged `a489c00`:
`docs/research/practitioner-pilot.md:775` (SC-2) and `:945` (recording table).
SC-2 requires the larger of 2 minutes and 25% of existing-tool time;
the template says `faster (≥2 min or ≥25 %)`.

**Reproduce:** existing tool 600 seconds, cfr-free 480 seconds. The saving
is 120 seconds / 20%. The template's OR labels it faster; SC-2's threshold
is 150 seconds, so it must be a tie.

**Harm:** observers following two parts of the same protocol classify the
same timing differently and produce incompatible descriptive evidence.
SC-2 is descriptive, not a CONTINUE gate; this finding does not claim it
directly changes that gate.

**Candidate manifest:** `docs/research/practitioner-pilot.md`.
**Acceptance:** use the same threshold in criterion, recording template,
instructions, and examples; distinguish equality/boundary cases. Keep the
operator's acceptance of proposed study criteria separate from this correction.
**Checks:** arithmetic examples below/at/above both thresholds, document
consistency/format checks, then the repo's pre-push gates.

## P1-20261021-06 — PR #105 demotes an explicitly requested exception

**Status:** OPEN on [PR #105](https://github.com/deffenda/cfr-free/pull/105).
**Implementation risk:** MEDIUM. **Evidence:** pinned PR head
`src/core/store.ts:1043-1045` and the corresponding SPEC change.
The guard checks `term.term.startsWith('exception')`; a quoted phrase is
one term and can contain `exceptions` after its first word.

**Reproduce:** seed these two rows with `makeSection`/`openTempStore`:

```text
4.85 heading: Evaluation of hearing impairment.
text: The hearing impairment exceptions are elsewhere.
4.86 heading: Exceptional patterns of hearing impairment.
text: The hearing impairment exceptions apply here. The hearing impairment exceptions govern this evaluation. Hearing impairment exceptions apply here.
```

Query `"hearing impairment exceptions"` produced `4.85, 4.86`.
The unquoted query produced `4.86, 4.85`. As a control, disabling ONLY the
demotion in memory restored `4.86, 4.85` for the identical quoted query.
No source file was modified for that control.

**Harm:** a user explicitly requesting exceptions receives the general
provision ahead of the exception because quoting bypasses the guard,
contrary to the proposed SPEC behavior.

**Candidate manifest:** reuse #105's `src/core/store.ts`,
`test/store.test.ts`, and corresponding SPEC/research text if needed.
**Acceptance:** recognize exception words within quoted terms while
preserving phrase semantics and intended demotion for general queries.
Test quoted/nonquoted forms, the no-exception control, and score ties.
**Checks:** store tests, benchmark regression run without expectation
changes, `npm run ci`, and fresh independent review of #105's new exact SHA.
