# cfr-free — Spec (v0.1 draft)

A self-hosted **38 CFR data service ("Titan")** plus an **MCP server**, TypeScript, vetted by local scanning gates (lint, strict TS, coverage floors, dependency audit + local security scanners).

## 1. Goals

- Index all of Title 38 CFR locally (SQLite + FTS5) from the public eCFR API.
- Expose the data two ways: an HTTP API (`serve`) and an MCP stdio server (`mcp`).
- Zero-infrastructure runtime: Node ≥ 22.5 built-ins only (`node:sqlite`, `node:http`).
- Local gates green: dependency audit clean, risky patterns lint-blocked, strict TS, high test coverage, low complexity.

**Non-goals:** titles other than 38 (design keeps `TITLE` a constant), auth/multi-tenant HTTP, vector/semantic search, live write-back to eCFR.

## 2. Architecture

Single npm package, one CLI (`cfr-free`) with subcommands (default: `mcp`):

```
cfr-free sync      # build/refresh the local index from eCFR
cfr-free serve     # start the Titan HTTP API (default 127.0.0.1:8787)
cfr-free mcp       # start the MCP stdio server (reads local index)
```

## 3. Data source & sync (live eCFR, one-shot)

Endpoints (base `https://www.ecfr.gov`, fixed origin — no SSRF surface):

1. `GET /api/versioner/v1/titles.json` → Title 38 `up_to_date_as_of` (fallback `latest_issue_date`). eCFR rejects dates past the issue date, so this is resolved every sync.
2. `GET /api/versioner/v1/structure/{date}/title-38.json` (~124 KB) → browse tree, stored in `meta`.
3. `GET /api/versioner/v1/full/{date}/title-38.xml` (~2 MB gzip'd, verified: 2953 SECTION + 17 APPENDIX DIVs, exact match with structure JSON) → parsed in one pass.

Parse rule: walk `<DIVn>` nodes by their `TYPE` attribute (`TITLE|CHAPTER|PART|SUBPART|SUBJGRP|SECTION|APPENDIX`), maintaining an identifier stack → each section gets `path`, `part`, `subpart` columns. Headings from `<HEAD>` (strip `§ 4.125 ` prefix). Sanity check: parsed count vs. structure count; hard-fail on 0, warn on mismatch.

**Image content (P1-01):** some provisions publish their rating tables as `<img>` elements (15 in the 2026-10-16 document, across 9 provisions — 1.9, 4.71, 4.71a, 4.76a, 4.77, 4.85, 17.610, 45.605, 59.50). The parser cannot include image content offline and must never drop it silently: every `<img>` — inline in a paragraph, nested in a container, or a direct content child — is replaced IN PLACE by the explicit marker `[image content not included: <path>]` in BOTH the text and the markdown representation. Only a vetted relative eCFR graphics path (`/graphics/<file>`, safe charset, no traversal) is named; any other source (scheme-qualified, host-qualified, outside `/graphics/`, or missing) yields `[image content not included: unrecognized image source]` and is never echoed. Nothing is fetched, OCR'd, or transcribed: the service stays fully offline, and a matching section count never implies complete textual coverage — the sync report states how many provisions carry the marker (`meta.image_content_sections`).

Sync is a single transaction: `DELETE FROM sections` + bulk insert (FTS5 external-content triggers keep the index consistent). Sync is atomic — readers never see a half-built index (SQLite WAL mode).

Policies: HTTP timeout 15 s, max response 50 MB, `User-Agent: cfr-free/<version>`, 2 retries (3 attempts) with 250 ms-per-attempt backoff on 5xx/429/timeouts only; no cache (cut — §10 row 11).

## 4. Storage schema (SQLite, FTS5)

```sql
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE sections (
  id INTEGER PRIMARY KEY,
  citation TEXT NOT NULL UNIQUE,     -- '4.125' | 'Appendix A to Part 4'
  kind TEXT NOT NULL CHECK (kind IN ('section','appendix')),
  heading TEXT NOT NULL,             -- 'Diagnosis of mental disorders.'
  chapter TEXT, subchapter TEXT, part TEXT, subpart TEXT, subject_group TEXT,
  path TEXT NOT NULL,                -- '/chapter:I/part:4/subpart:B/...'
  text TEXT NOT NULL,                -- plain text
  markdown TEXT NOT NULL,            -- rendered markdown
  issue_date TEXT NOT NULL
);
CREATE VIRTUAL TABLE sections_fts USING fts5(
  citation, heading, text, content='sections', content_rowid='id',
  tokenize='porter unicode61'
);
-- standard ai/ad/au sync triggers
```

**FTS query safety:** user input never passes through raw. `toFtsQuery()` tokenizes on `[^\p{L}\p{N}]`, emits `"tok"*` terms joined by `AND`; service retries once with `OR` if `AND` yields 0 rows. Bound inputs: query 3–200 chars, `per_page` 1–20, page ≥ 1. Results deduped by citation (eCFR search returns one row per change event).

Hardening: no request bodies, zod-validated query strings, router-level byte caps (URL ≤ 2048 bytes → `414 uri_too_long`; `q` ≤ 800 bytes, `part` ≤ 10 bytes → `400`), per-peer token-bucket rate limiting (`429` + `Retry-After`) when `CFR_ALLOW_REMOTE=1` (loopback default never throttles; a peer is a socket address, so clients behind one NAT share a budget — fine for a coarse DoS guard, not per-user fairness), `X-Content-Type-Options: nosniff`, request timeout, 404/405/400 with machine-readable error JSON, `Cache-Control: max-age=3600` on section reads (content only changes on amendment); the two eCFR-fetching routes cache their per-call fetches at shorter ceilings (`diff` `max-age=3600`, `redline` `max-age=300` — a redline spans two upstream fetches and the from/to window is only rarely an identical document). No auth — documented as localhost-only; `HOST` env can override deliberately (with the rate budget attached).

The API is JSON-only except for two deliberate text routes: `GET /metrics` serves Prometheus exposition text (gauges: `cfr_free_sections`, `cfr_free_appendices`, `cfr_free_stale`, `cfr_free_max_age_days`, `cfr_free_issue_date_timestamp_seconds`, `cfr_free_synced_at_timestamp_seconds`, `cfr_free_structure_drift` when recorded, and `cfr_free_disk_free_bytes`/`cfr_free_disk_total_bytes` when a statfs snapshot exists) so scrapers need no JSON parsing — it returns the same read-only data as `/health` — and the read-only UI asset routes (`/`, `/ui.js`, `/ui.css`) serve `text/html`/`text/javascript`/`text/css` (§6-R5 batch-6 addition: static strings compiled from `src/titan/ui.ts`, served with `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, same-origin CORP, and a `default-src 'none'` CSP on the document; the UI consumes the same JSON API above).

Machine-readable contract: [`docs/openapi.yaml`](openapi.yaml) (OpenAPI 3.1, derived from `src/titan/http-server.ts` — keep in sync).

## 6. MCP tools (all read-only annotations)

1. `search_regulations(query, page?, per_page?, part?)` → ranked hits with citations, snippets, bm25 scores and the query terms visible in each hit (`matches`). A query that _is_ a citation (`4.130`, `38 CFR 4.16`, `§ 3.350(a)`) pins that exact section as the first hit (page 1 only; totals include the pin on every page); quoted spans search as exact phrases; curated claims acronyms (ptsd, tdiu, smc, mst, dic, tbi, hlr, bva, nsc) expand to their regulatory phrases; every response carries the `indexIssueDate`/`indexStale`/`notice` freshness envelope and hits carry `citationDisplay` + `sourceUrl`.
2. `get_section(citation)` → accepts `4.125`, `§ 4.125`, `38 CFR 4.125`; returns markdown text, heading, path, issue date, eCFR source URL, and `references[]` (every `§`/`38 CFR` cross-cite in the text with a local-availability flag). A citation that misses the index returns actionable guidance instead of a bare 404: reserved/removed/outside-Title-38 possibilities, the eCFR verify link, and indexed sections that mention it. Stale-index notices also link the eCFR point-in-time form (`/on/<date>/title-38/section-<citation>`) for date-of-claim/CUE analysis.
3. `browse_title38(chapter?, part?, subpart?)` → structure children at that level.
4. `index_status()` → freshness (issue date, synced at, staleness vs. `CFR_MAX_AGE_DAYS`, structure-drift flag) plus `lastChanges`: what the most recent sync amended/added/removed at the provision level (per-citation sha256 diff across the wholesale rebuild, capped lists, `baseline` flag on first sync, `parserChanged` guard against re-extraction noise).
5. `list_parts()` → every part present in the index with its structure-tree title and section/appendix counts.
6. `health()` → one-call readiness verdict: `ready` | `stale` | `degraded` (structure drift — provisions may be missing; precedence empty → degraded → stale → ready) | `empty` (plus issue date and last sync) for clients gating queries.
7. `diff_issues(from_date, to_date)` → provision-level diff of Title 38 between two eCFR issue dates: `changed`/`added`/`removed` citation lists (each capped at 100 with `truncated: true` when any list was cut), plus both issue dates echoed back. Both dates are **required** (no default-`to` — the CLI's `cfr-free diff <from>` keeps that convenience); identical or impossible dates (`2026-13-01`) are rejected as `invalid_input` before any fetch. Statelessness costs a network round-trip per call: both dates' full-title XML is fetched from eCFR and hashed per citation on the fly (no cache, no local index), so these are the two tools that are **not** offline — both are registered only when an eCFR client is injected (`serve`/`mcp` do; a client-less server keeps the six local-index tools).
8. `redline(from_date, to_date, citation)` → line-level redline of one provision between two eCFR issue dates: every line of the cited provision as of each date — `same`/`add`/`del` hunks with 1-based anchors into each side's text, an `added`/`removed`/`unchanged`/`changed` status, both sides' raw text, and a `coarse` flag when either side exceeded the core's 2000-line cap (two whole-text blocks instead of an LCS walk). The dates are SELECTORS — eCFR serves the revision in force on the requested date; they are not a verified stamp of which issue date was served. Both dates are **required**; identical or impossible dates are rejected as `invalid_input` before any fetch, and a citation missing from BOTH dates is `not_found` after the fetches. Same open-world, eCFR-client-gated registration as `diff_issues`.

All return MCP `structuredContent` + text content. The six index-backed tools are `readOnlyHint: true`, `openWorldHint: false` (post-sync: no network); the seventh and eighth, `diff_issues` and `redline`, are `readOnlyHint: true`, `openWorldHint: true` (registered only when an eCFR client is injected; hit the live versioner per call). Beyond tools, the server registers three read-only **resources** — `cfr://index/status` (freshness JSON), `cfr://title38/parts` (parts list), and `cfr://title38/definitions` (§ 3.1 master definitions section detail) — and two **prompts**: `cfr_research` (`topic`, `part?`) encoding the search → read → cite workflow, and `cfr_claim_evaluation` (`issue`, `part?`, `citation?`) encoding the adjudicator workflow (health gate → locate criteria → quote verbatim → follow `references[]` → paste-ready citations with source URLs and issue date). Startup: if index missing or older than `CFR_MAX_AGE_DAYS` (default 7) and `CFR_AUTO_SYNC != 0`, sync first (progress → stderr), then serve. No stdout logging ever.

## 7. Security plan

- **Deps:** runtime deps limited to `@modelcontextprotocol/sdk`, `zod`, `fast-xml-parser`; lockfile committed; `npm audit --audit-level=high` runs in the quality job, and `npm run scan` adds osv-scanner, gitleaks, trivy, semgrep locally. No hosted scanner service: the operator withdrew hosted code-scanning gates permanently (2026-10-18), so these local gates are the security floor.
- **Code (quality):** `strict` + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`; ESLint (recommended, `no-explicit-any=error`, `no-console` allow-only-`error`, `complexity ≤ 10`, `eqeqeq`); no regex without linear guarantees; no `eval`/`Function`/`child_process`; no secrets (none needed); all error paths return sanitized messages (no stack traces to clients).
- **Coverage:** vitest + v8 ≥ 90 % branches/lines/functions/statements (fail-under thresholds in `vitest.config.ts`); mocked-fetch tests (no live network in PR CI).
- **CI:** GitHub Actions — quality job (lint, typecheck, test, build, audit) + security job (gitleaks, osv-scanner) + docker job; no hosted-scanner job exists.

## 8. Test plan

Unit: citation parser, FTS sanitizer (incl. injection attempts `" OR 1=1--`), XML renderer (tables, authority/source-credit nodes, reserved sections), store queries (temp SQLite), sync with mocked eCFR payloads (count-mismatch warning, 0-section hard-fail). Integration: MCP via `InMemoryTransport` (tools/list + every tool + resources/prompts), HTTP API via ephemeral port + `fetch`. Live: `test/live.test.ts` gated behind `LIVE_TESTS=1` (full real-eCFR sync + read consistency; hard-skipped otherwise), exercised by the weekly Live E2E workflow.

## 9. Risks / open questions

1. `node:sqlite` experimental warning on some Node versions (stderr only; harmless to stdio JSON-RPC).
2. `fast-xml-parser` v5 API drift vs v4 — covered by renderer tests.
3. eCFR `/search/v1/results` is a change-index (dup rows) — mitigated by dedupe; primary search is local FTS5 anyway (search tool uses local index; eCFR search only used pre-index?).
4. Title 38 only — other titles later require re-running sync for that title (schema stores no title column; keep `TITLE = 38` constant for v1).

## 11. GitHub delivery (best practices)

- Public repo `deffenda/cfr-free`, **MIT** license.
- Trunk-based flow: bootstrap `main` (docs/license only) → feature branch → **PR** → CI green → **squash merge** + branch delete.
- Branch protection on `main`: PR required, strict up-to-date, required checks `quality (22)` + `quality (24)` + `security` (the `security` context is required per the live protection config; `docker` runs in CI as gate evidence but is not itself required). Review process: **AI multi-model review required for every PR** — see [`AGENTS.md`](../AGENTS.md) and [`claude/rules/cross-model-review.md`](../claude/rules/cross-model-review.md) (the historical "no mandatory review (solo maintainer)" posture is superseded; solo-maintainer practice was documented in CONTRIBUTING).
- Repo settings: squash merge only, auto-delete head branches, Dependabot (npm + actions weekly), all workflow Actions **SHA-pinned** (Dependabot re-pins on updates), minimal `GITHUB_TOKEN` permissions (`contents: read`).
- Local pre-push gates: `npm run ci` + `npm run scan` (npm audit, osv-scanner, gitleaks, trivy, semgrep).
- Container (v0.5): multi-stage `Dockerfile` (node:22-alpine, non-root, index in `/data` volume); CI `docker` job builds the image and runs a hermetic offline smoke (no eCFR in PR CI). `release.yml` on `v*` tags runs the full CI gate + a live container e2e (real sync, HTTP surface, MCP `list_parts` handshake), then publishes multi-arch (`linux/amd64` + `linux/arm64`) `ghcr.io/deffenda/cfr-free:{version,major.minor,latest}` with SLSA provenance attestation — built-in `GITHUB_TOKEN` only, no secrets.
- Live E2E: `.github/workflows/live-e2e.yml` runs `LIVE_TESTS=1` against real eCFR on a weekly cron and on `workflow_dispatch` (format-drift tripwire); PR CI stays hermetic.
